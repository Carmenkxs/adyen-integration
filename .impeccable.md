## Design Context

### Users
The builder themselves, testing and iterating day to day, plus occasional demoing of the
project to others (e.g. presenting the work). Not a real merchant's customers — this is a
backend Adyen sandbox integration, and these pages are the minimal front-end needed to
exercise and demonstrate it (a demo cart, the Drop-in checkout page, and the payment
result/return page).

### Brand Personality
Clean and technical. Understated, precise, like a well-made internal tool or API
reference page — not a consumer storefront, not a marketing site. Nothing flashy;
legible and considered instead.

### Aesthetic Direction
Light mode only (this is a daytime testing/demo tool, no dark-mode need). Neutral palette
tinted toward a cool slate/blue-gray, with a confident but restrained accent color for
primary actions, and clear semantic colors for payment outcomes (success/decline/pending)
that read at a glance without shouting. Typography: Red Hat Display (headings) + Red Hat
Text (body) + Red Hat Mono (order references, amounts, technical identifiers) — a
cohesive, enterprise-software-appropriate pairing designed for exactly this register.
Anti-references: no consumer e-commerce styling, no playful/rounded/pastel treatment, no
mimicry of Adyen's own brand colors (this is Shop A's integration, not an Adyen-branded
surface).

### Design Principles
1. One shared stylesheet and a small set of reusable components (page shell, panel,
   button, status message with semantic tone variants) — not per-page bespoke CSS.
2. Status/result messaging carries a semantic tone (success/danger/neutral) determined by
   the same lookup that supplies the copy, so visual treatment and wording never drift
   apart.
3. Narrow, single-column layouts (these are checkout-style pages, not dashboards) —
   readable measure, generous whitespace, no dashboard-style card grids.
4. No side-stripe borders on status messages, no gradient text, no generic drop-shadow
   card templates — full background tints and typography carry the hierarchy instead.
